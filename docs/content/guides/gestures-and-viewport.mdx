# Gestures & viewport

All navigation is handled inside the chart — you don't wire up any gesture code.

<Tabs groupId="platform" queryString>
<TabItem value="react-native" label="React Native">

| Gesture | Effect |
| --- | --- |
| Drag (one finger) | Scroll through time; vertical drag moves the price window |
| Pinch | Zoom around the focus point |
| Drag the price axis (right) | Rescale price only |
| Drag the time axis (bottom) | Rescale time only |
| Long-press | Show the snapping [crosshair](crosshair-and-events.mdx) |

</TabItem>
<TabItem value="web" label="Web">

| Input | Effect |
| --- | --- |
| Drag | Scroll through time; vertical drag moves the price window |
| Wheel scroll (vertical) | Zoom the time window around the cursor |
| Horizontal scroll / shift+wheel | Pan through time |
| Ctrl/⌘+wheel or trackpad pinch | Zoom both axes around the cursor |
| Drag the price axis (right) | Rescale price only |
| Drag the time axis (bottom) | Rescale time only |
| Hover (mouse) | Show the snapping [crosshair](crosshair-and-events.mdx) under the cursor |

</TabItem>

## Controlling the visible window

By default the chart shows a sensible recent window on first render. To control
it explicitly, pass [`visibleRange`](../reference/index.md):

```tsx
<VroomChart
  candles={candles}
  visibleRange={{ startMs: 1700000000000, endMs: 1700090000000 }}
/>
```

Omit it (or pass both `0`) to fit all candles. When you do drive `visibleRange`,
treat [`onViewportChange`](crosshair-and-events.mdx) as the source of truth for the
current window after the user pans/zooms, and feed it back into state if you want
a fully controlled chart.

## Framing by candle width

Instead of an explicit time window, you can frame the first view by candle **size**.
Pass [`defaultCandleWidth`](../reference/index.md) (px) and the chart picks the
initial zoom so each candle body renders about that wide:

```tsx
<VroomChart candles={candles} defaultCandleWidth={8} />
```

Larger values are more zoomed in (fewer, wider candles); smaller values are more
zoomed out. This only affects the **initial** framing (and `reset`) — the user can
still pan and zoom freely afterward, and an explicit `visibleRange` takes precedence.
It's handy for keeping candles a consistent size across devices of different widths.

If the series is shorter than that window (a new listing with nine daily bars, say),
the extra space is empty slots to the left of the first candle. The bars stay
`defaultCandleWidth` wide instead of stretching to fill the plot. Dragging that
view is a no-op: the candles stay on the right edge instead of snapping to the
left and locking.

## Sizing

The chart fills its parent, so prefer layout-driven sizing via `style` (flex,
`aspectRatio`, or absolute fill). Pass explicit `width` / `height` only to
override measured layout. See [`VroomChartProps`](../reference/index.md).
