# vroom

## Project overview

**vroom** is an open-source, Skia-powered candlestick charting library that runs on React Native (iOS, Android coming) and the web (React DOM). A single C++ rendering core drives all platforms, delivering 60+ FPS pan, pinch, and zoom with a native feel.

Published packages:

| Package | npm name | Platform |
|---|---|---|
| React Native | `react-native-vroom-chart` | iOS via JSI + Skia (Android in progress) |
| React (web) | `@vroomchart/react` | React DOM via Skia-WASM |
| Core (web) | `@vroomchart/core-wasm` | Framework-agnostic WASM + Canvas2D fallback |

Shared TypeScript types live in `@vroomchart/types` (private, bundled into published packages).

**Tech stack:** C++17 (Skia renderer), TypeScript (packages, types), Emscripten (WASM build),
pnpm workspaces (monorepo), Changesets (versioning), Docusaurus (docs), tsup (bundling),
vitest (TS unit tests), doctest (C++ unit tests).

## Reference

### Package layout

```
packages/
  core/          Platform-agnostic C++ engine (Skia). Public `extern "C"` facade in vroom_chart.h.
  core-wasm/     WASM glue + JS loader. Loads Skia-WASM, exposes loadVroom() → VroomModule.
  react/         React DOM wrapper around core-wasm. VroomChart component + drawing tools.
  react-native/  React Native wrapper. JSI bridge + iOS/Android shims around the C++ core.
  types/         Shared TS types (Candle, VroomTheme, CrosshairEvent, indicator configs, etc.).
                 Private — bundled into core-wasm/react/react-native; never published alone.
docs/            Docusaurus site. Content in docs/content/; API reference auto-generated by
                 docusaurus-plugin-typedoc from packages/react-native/src/index.ts.
examples/        test-bench (Expo dev client) + web-demo (Vite).
third_party/     Fetched Skia prebuilts (gitignored).
```

### Architecture

```
C++ core (Skia)
  ├── extern "C" facade (vroom_chart.h)
  ├── JSI bridge ──► react-native-vroom-chart (iOS native)
  ├── WASM compile ──► @vroomchart/core-wasm ──► @vroomchart/react (web)
  └── (future: JNI for Android, FFI for Swift/Kotlin standalone packages)
```

The core owns all drawing. Platform wrappers own the canvas surface and gesture forwarding.
WASM assets are bundled inside `@vroomchart/core-wasm`; consumers don't host them.

## Essential commands

All commands run from the repo root with pnpm.

```sh
# Install everything
pnpm install

# Build all published packages (tsup only — WASM binaries are committed)
pnpm build:packages

# Build WASM (only when C++ core changes — requires emsdk + Skia checkout)
source ~/emsdk/emsdk_env.sh
SKIA_DIR=/Users/darion/skia pnpm --filter @vroomchart/core-wasm build:wasm
# Output: packages/core-wasm/assets/

# Typecheck all packages
pnpm -r --filter './packages/*' run typecheck

# Run TS unit tests (vitest)
pnpm --filter @vroomchart/react --filter react-native-vroom-chart run test

# Run C++ unit tests (Skia-free TUs only — no Skia dependency for CI)
pnpm test:core

# Run full CI check locally (build + typecheck + test + audit)
pnpm build:packages && pnpm -r --filter './packages/*' run typecheck && pnpm --filter @vroomchart/react --filter react-native-vroom-chart run test && pnpm audit --audit-level high

# Docs dev server
pnpm docs

# Build docs + regenerate API reference
pnpm docs:build
# After changing public types, run this and commit the regenerated docs/content/reference/

# React Native test bench
pnpm start          # Expo dev client
pnpm rebuild:ios    # Rebuild native iOS after native module changes

# Web demo
pnpm --filter web-demo dev --port 5199 --strictPort
```

## Patterns

### Build order is critical

1. C++ core changes → rebuild WASM first, then build dependent TS packages
2. TS packages resolve each other via built `dist/` — always build a package before typechecking its dependents
3. CI skips the WASM build (binaries are committed), so `pnpm build:packages` is tsup-only

### What to rebuild when

| You changed | Rebuild |
|---|---|
| `packages/core/` (C++) | `build:wasm` → `build:packages` |
| `packages/core-wasm/src/` | `pnpm --filter @vroomchart/core-wasm build` → `pnpm --filter @vroomchart/react build` |
| `packages/react/src/` | `pnpm --filter @vroomchart/react build` |
| `packages/react-native/src/` | `pnpm --filter react-native-vroom-chart build` |
| `packages/types/src/` | `pnpm build:packages` (everything that bundles it) |

### Sharing types across platforms

`@vroomchart/types` defines the canonical public API types. Both `@vroomchart/react` and `react-native-vroom-chart` re-export them. When adding a new public type:

1. Define it in `packages/types/src/index.ts`
2. Re-export it from `packages/react/src/index.ts` and `packages/react-native/src/index.ts`
3. Run `pnpm docs:build` and commit the regenerated reference

### Changesets

This repo uses [Changesets](https://github.com/changesets/changesets) for versioning.
After making a user-facing change that needs a version bump:

```sh
pnpm changeset
```

Select the affected packages and choose a semver bump (major/minor/patch).
Commit the generated `.changeset/*.md` file alongside your changes.
CI enforces that every PR touching published packages includes a changeset.

### Testing web demo visually

The web demo (`examples/web-demo/`) is a Vite app. Drive it with headless Playwright:

```sh
pnpm --filter web-demo dev --port 5199 --strictPort   # start in background
```

Key Playwright selectors (top bar): `Repro`/`Demo` view buttons, `BTC`/`SOL` asset buttons,
`1m`/`5m`/`15m`/`1h` timeframe buttons, first `input[type=checkbox]` (seriesKey).
The chart renders to a `<canvas>` — verify by reading screenshots, not DOM.
Wait ~2.5s after load for WASM init, ~700ms after each interaction before screenshotting.
Ignore Skia "Shader compilation error" console messages — harmless.

## Anti-patterns

- **Don't edit `docs/content/reference/` by hand.** It's generated by `docusaurus-plugin-typedoc`.
  Edit the TypeScript source (JSDoc + types), run `pnpm docs:build`, and commit the result.
- **Don't skip the build order.** Editing types or core-wasm without rebuilding dependents
  will cause stale type errors. If `pnpm -r run typecheck` passes but an editor shows
  red, rebuild the dependency chain.
- **Don't add a `version:` to the pnpm action-setup in CI workflows.** The version is
  already declared in root `package.json`'s `packageManager` field — specifying it in
  both places breaks the action.
- **Don't pin TypeDoc source links to a commit SHA.** The `docs/docusaurus.config.js`
  pins to `gitRevision: 'main'` so generated source links don't change every commit
  (which would make the CI "reference is committed" check fail every push).

## Code style

- **TypeScript**: Strict mode, ES modules only (`"type": "module"` in published packages).
  No default exports — use named exports everywhere.
- **C++**: C++17. Public surface is C (`extern "C"`). Internal code uses modern C++.
- **Commits**: [Conventional Commits](https://www.conventionalcommits.org/).
  Common types: `feat`, `fix`, `docs`, `chore`, `ci`, `build`, `refactor`, `publish`.
  Scopes when relevant: `react`, `core-wasm`, `react-native`, `web-demo`, `core`, `docs`.

## Commit and pull request guidelines

### Before committing

1. If you changed C++: rebuild WASM (`build:wasm`) and commit the regenerated assets
2. If you changed TS types: rebuild all packages (`build:packages`) and regenerate docs (`docs:build`)
3. Run `pnpm build:packages && pnpm -r --filter './packages/*' run typecheck && pnpm --filter @vroomchart/react --filter react-native-vroom-chart run test`
4. If you touched a published package: add a changeset (`pnpm changeset`)

### PR requirements

- CI must pass: build + typecheck + test + audit + docs freshness check
- Every PR touching published packages must include a changeset
- Dependabot PRs are auto-merged after CI passes
- Security-sensitive changes: report via [GitHub Security Advisory](https://github.com/keepitreal/vroom/security/advisories/new), not a public PR
